# TG Persona · Telegram 人形分身

部署在小型 VPS 上的个人账号自动回复工具。**不是机器人**——登录你自己的 Telegram 账号,监听的群里有人发你设定的关键词时,以你的身份回复文本 / 点表情。全部通过 **Web 面板可视化管理**(http://IP:端口)。

## 功能

- **可视化 TG 登录**:面板里填 API_ID / API_HASH → 手机号 → 验证码 → (两步验证密码),会话持久保存,重启免登录;登录后自动同步头像
- **面板安全**:密码用 scrypt 哈希存储;随机会话令牌由服务端严格校验 30 天有效期;连续输错 3 次要求 PNG 位图验证码(一次性、3 分钟),10 次锁定 10 分钟;默认不信任伪造的代理头,改密必须验证原密码;HTTPS 下自动启用 Secure Cookie
- **群管理**:列出账号加入的所有群(可搜索),一键加入 / 取消监听
- **关键词规则**:
  - 关键词多词逗号分隔(任意命中)、支持正则
  - 动作三选一:回复文本 / 点表情 / 回复+表情
  - 回复内容多条用 `||` 分隔,随机选一条,更像真人
  - **生效群**:每条规则可单独勾选只在哪几个群生效(不勾 = 全部监听群)
- **自动化任务**(「自动化」页,四类):
  - **签到**:每天在设定时间窗口内随机时刻执行;命令支持 `|` 多条随机、`{num:N}` `{word:N}` `{alpha:N}` `{uuid}` 随机占位符;可自动点回复按钮、成功/失败关键词判定、积分正则提取、发送失败重试(0-5)、发到群组
    - **按表情找按钮**:有些 bot 按钮文字每次都变(「好运来临」/「命中注定」)但图标不变,填表情(如 🧧)即可稳定命中
    - **连点**:部分 bot 需要连点多次才生效,可设「连点次数 1-20 + 间隔 50-3000ms」,每次点击前重新抓取最新按钮
  - **抢注监控**:监听群内邀请码/开注消息,自动回复或群内发送注册文本(`{code}` 占位符);**轮询模式**可选:每隔 N 秒主动探测机器人,出现开注关键词立刻注册
  - **抢红包**:群里出现红包/🎁消息自动点领取按钮
  - **自定义多步任务**:JSON 步骤流(发消息 / 等待 / 点按钮(任意、AI 选按钮)/ 识别并提交验证码 / 等回复匹配),整条失败可链级重试
- **验证码识别**:自定义任务里的「验证码」步骤优先调用 OpenAI 兼容视觉 API,未配置则用服务器本地 OCR(ddddocr,安装脚本自动装)
- **识别与 AI 测试**:在「自动化 → 验证码识别」上传 PNG/JPG/WebP 测试图(最大 2MB)，可选验证码字符数；显示识别文本、实际通道、耗时和回退原因。点「测试 AI 连接」会发送仅回复“测试成功”的提示并展示真实回复。测试使用当前填写参数，不自动保存；图片只在点击识别后上传，不落盘。密钥以密码框显示，测试错误会隐藏密钥。AI 测试可能产生服务商 API 费用；文本连接成功不代表模型支持图片，请再用上传测试确认。
- **群保号(定时发言)**:每隔自定义时间(分钟/小时/天)在指定群发一条内容(支持 `||` 多条随机与占位符),可设置发送后 N 秒自动删除(Emby 保号常用);有「执行」按钮可立即发一条
- **通知推送**:签到成功/失败、抢注命中、自定义任务结束可选推送到 Bark 或 Telegram Bot(成功/失败分别开关)
- **自动水群(从众)**:默认关闭;开启后,监听群里同一句话短时间(默认 5 分钟)出现多人(默认 5 条)时,你也随机跟一条话术,像真人融入群聊;命令类消息不跟
- **时区设置**:面板里选时区(默认 `Asia/Shanghai`),签到窗口与"今天已签"都按它计算;VPS 是 UTC 也不用改系统时区
- **拟人化参数**:命中后随机延迟(默认 1~3 秒)、同群同规则冷却(默认 20 秒)、忽略机器人消息
- **主题与外观**:亮色 / 暗色主题一键切换(跨设备同步)、自定义头像、移动端友好 UI
- **日志管理**:默认保留 30 天自动清理(设置里可改,0=永久),支持按「清理 30 天前 / 清空全部」手动删除;支持按群名/发送人/消息内容搜索
- **会话守护**:每分钟检测 TG 状态,临时故障不当作确定登出,异常状态仍继续复查;恢复后自动复位通知状态
- **在线更新与版本号**:继续拉取 `main`,开始时锁定其提交快照;安全解包、校验、备份、依赖安装、替换、重启和健康检查,失败自动恢复代码/版本并尝试重启旧版;更新状态跨重启保存。会话与数据库不被覆盖;依赖安装可能修改 venv,不承诺依赖自动回滚
- **多条规则同时命中**:一条消息可以同时触发多条规则(每条各自冷却),不再只执行第一条
- **运行面板**:总览统计、日志按类型分开(回复/签到/抢注/红包/自定义)、点一行展开完整记录(谁在哪个群发了什么、我回复/点了什么)、暂停/恢复开关、任务复制、面板密码修改

## 安全提示(重要)

面板默认监听 `0.0.0.0`,直接暴露在公网时请至少做一件事:

```bash
# 方案 A:只监听本机,用 SSH 隧道访问(最简单)
sed -i 's/--host 0.0.0.0/--host 127.0.0.1/' /etc/systemd/system/tg-persona.service
systemctl daemon-reload && systemctl restart tg-persona
# 本地:ssh -L 8090:127.0.0.1:8090 root@你的服务器 → http://127.0.0.1:8090

# 方案 B:nginx 反代 + Let's Encrypt HTTPS
# 方案 C:至少用 ufw 只放行你自己的 IP
```

面板密码只有在**首次启动**时来自 `data/panel_password.txt` 或 `PANEL_PASSWORD` 环境变量,
之后会转成 scrypt 哈希存入 `data/config.db`,明文文件被自动删除。忘记密码时:

```bash
systemctl stop tg-persona
sqlite3 /opt/tg-persona/data/config.db "delete from settings where key='panel_pw_hash'"
PANEL_PASSWORD=新密码 /opt/tg-persona/venv/bin/python -m uvicorn main:app --port 8090   # 启动一次写回哈希
systemctl start tg-persona
```

## 部署(VPS,以 Debian/Ubuntu 为例)

**一键询问式安装(推荐)** — 脚本会询问你要用的端口和面板密码:

```bash
# 1. 拉取仓库
git clone https://github.com/MakkaPakka518/TG-Persona.git /opt/tg-persona
cd /opt/tg-persona

# 2. 运行询问式安装脚本(root 执行)
sudo ./install.sh
```

脚本会依次询问:
- **监听端口**(默认 8090)
- **面板登录密码**(回车自动生成随机密码)

随后自动完成:创建 venv → 安装依赖 → 注册 systemd 服务 → 启动,最后打印访问地址和密码。

**手动部署**(想自己控制每一步时):

```bash
# 1. 上传项目到服务器
#    scp -r tg-persona root@你的VPS:/opt/
#    (或 git clone https://github.com/MakkaPakka518/TG-Persona.git /opt/tg-persona)

# 2. 安装依赖
sudo apt update && sudo apt install -y python3 python3-venv
cd /opt/tg-persona
python3 -m venv venv
./venv/bin/pip install -r requirements.txt

# 3. 配置 systemd 服务(先编辑路径和端口)
sudo cp tg-persona.service /etc/systemd/system/
#   ExecStart 必须使用已安装依赖的 venv/bin/python，保留 --no-proxy-headers。
#   可用 data/panel_password.txt(600)预置首次密码，不要把密码写进 unit。
sudo systemctl daemon-reload
sudo systemctl enable --now tg-persona

# 4. 查看启动状态；未预置密码时，随机密码仅在首次启动日志显示一次
sudo systemctl status tg-persona
sudo journalctl -u tg-persona -n 50 --no-pager
# data/panel_password.txt 启动后已经删除，密码只以哈希存于数据库。
```

之后浏览器打开 `http://你的VPS的IP:端口`,输入面板密码进入。

## 使用流程

1. 打开面板 → 输入面板密码 + 图形验证码进入
2. 进入「设置 → Telegram 账号」:**第 1 步**填 API_ID / API_HASH —— 去 [my.telegram.org](https://my.telegram.org) → API development tools → 登录后创建应用获取
3. **第 2 步**:填手机号(带国家码,如 `8613800138000`)→ 发送验证码
4. **第 3 步**:填 TG 发来的验证码;若账号开了两步验证,再填 Cloud 密码
5. 进入「群组」,搜索并加入要监听的群
6. 进入「规则」,添加关键词规则(如关键词 `求推荐,有没有` → 回复文本 `好的我看看||来了来了` 或点 `👍`)
7. 进入「自动化」,按需添加签到 / 抢注 / 抢红包 / 自定义任务(任务支持一键复制)
8. 完成。群里有人命中关键词,你的账号会自动回复/点表情;自动化任务会按计划执行并在「日志」留痕

## 在线更新(喂饭步骤)

1. 在「设置 → 系统更新」检查最新版本。**始终取 `main`，不是 Release**；一次更新的 VERSION 和代码锁定到同一个 main 提交，避免下载过程中分支变化造成混包。
2. 有新版本时点「立即更新」；版本号相同也可以确认后强制拉取 main 最新代码。
3. 进度依次为下载、解包校验、备份、依赖、替换、重启、健康检查。只有新服务连续通过健康检查才显示成功；重启期间网页保持轮询，状态写入 `data/update-state.json`。
4. 失败自动恢复原代码与 VERSION，新版新增的文件也会移除；若已重启则尝试恢复旧服务。回滚失败会明确显示需人工处理，不会误报成功。
5. 准备线程/监督器意外退出后，下一次更新请求会检查进程身份与事务标记：未覆盖的旧任务解除状态，已覆盖但未确认的事务先恢复，不会直接覆盖另一份代码；恢复失败可重试恢复或按备份 manifest 人工处理。

> 更新不覆盖会话、数据库、密码、`.git`、`.env` 等本地数据。依赖安装使用应用解释器，pip 失败也可能已经改变部分依赖；代码可自动回滚，**依赖环境不保证自动回滚**。
> systemd 部署需要 `systemctl` 和 `systemd-run`，监督更新的临时服务独立于应用，避免被重启杀掉。非 systemd 仅支持单进程 `python main.py` 或 `python -m uvicorn main:app`；不支持的管理器、多 worker/reload 或无法确认健康地址会在覆盖前拒绝更新。
> 服务器需能访问 api.github.com、raw.githubusercontent.com、codeload.github.com；检查 main 使用 GitHub API，受其访问限额约束。
> 备份目录含 manifest 与原文件，恢复方法见下方补充说明。

## 安全说明

- Telegram 账号会话保存在 `data/tg.session`,目录权限 700 / 文件 600
- 面板密码启动后只以 scrypt 哈希存于 `data/config.db`；随机 token 鉴权、30 天服务端过期；图形验证码为 PNG 位图
- 改密必须填写原密码；改密会注销全部旧 token 并为当前设备换发新 token
- 不建议把面板端口(8090)直接暴露公网;可用防火墙限定 IP,或通过 Nginx 反代加 HTTPS
- 提示:频繁回复可能触发 Telegram 限流(代码会自动等待 FloodWait),请合理设置冷却时间

## 常见问题

- **收不到验证码**:确认手机号带国家码;Telegram 要求号码前不要加 `+`
- **登录后群列表为空**:确认登录的是你自己加入了群的账号
- **改了端口**:编辑 service 里 `--port` 或设环境变量 `PORT`,然后 `sudo systemctl daemon-reload && sudo systemctl restart tg-persona`
- **日志怎么调大**:`sudo journalctl -u tg-persona -f` 实时查看

## 手动打包发布与 VERSION 同步

GitHub → Actions →「发布公开版」→ Run workflow，选择 `main`：

- **版本号留空**：优先使用根目录 `VERSION`。若这个版本已经有发布标签，则在当前文件/已发布版本的最高值上递增 patch。
- **手动填写**：接受 `1.2.3` 或 `v1.2.3`，不允许已有标签或版本倒退。
- 流程先跑隔离回归，再把最终版本写为 `VERSION` 的 `1.2.3`；若文件发生变化，自动提交回 `main`。
- 从**同一个提交**生成 `v1.2.3` 标签、tar.gz、zip 与 SHA256SUMS，再原子推送 main 和标签，最后创建 Release/上传安装包。
- 发布过程中 main 被别人推进，流程会拒绝过时快照，不强推，也不会留下半成功的远端标签。
- 工作流需要仓库内容写权限；若 main 有分支保护，还需允许工作流的版本同步提交，否则会明确失败。

**在线更新仍拉 main，发布并不会把更新来源改成 Release。** 本版本 `VERSION=1.4.1`，首次留空发布将使用 `v1.4.1`。

## 反向代理与 HTTPS

新安装已禁用 uvicorn 自动代理头解析。旧服务请在 ExecStart 中补上 `--no-proxy-headers`；应用仅按 `TRUSTED_PROXIES` 明确配置的 IP/CIDR 信任代理，默认不信任任何代理。

本机 nginx 示例（服务绑定 127.0.0.1，TLS 在 nginx 终止）：

```ini
# systemctl edit tg-persona
[Service]
Environment="TRUSTED_PROXIES=127.0.0.1,::1"
ExecStart=
ExecStart=/opt/tg-persona/venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8090 --no-proxy-headers
```

```nginx
location / {
    proxy_pass http://127.0.0.1:8090;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

不要设置全网可信 CIDR，也不要允许客户端绕过代理直接访问后端。HTTPS 下自动设置 Secure cookie；HTTP 为兼容现有部署保留，但不适合直接暴露公网。更新代码不会替你签发证书或修改 VPS 的 nginx/systemd 配置。

## 自动任务状态与失败重试

- 签到编辑页可分别设置「发送命令后延迟」和「点击按钮后延迟」，单位秒，范围 0–120；默认 1.6 / 2 秒，0 表示立即进行。
- 连点可选「刷新按钮状态」和「复用同一按钮」。默认刷新；固定模式不在连点期间重新拉取消息，适合一直不变的按钮。
- 图片步骤排除已有欢迎图/错误卡片，要求本次动作后的明确验证提示；支持迟到提示与同消息更换图片，不能仅改卡片文字就当作新图片。
- 提交验证后等待机器人本轮明确成功反馈；常见拒绝提示始终优先判断，不再因未配置失败关键词或发送成功而误记为成功。日志显示图片来源消息、两段延迟、连点模式和失败原因。

- `last_at` 只记录成功；`last_attempt`、失败次数、下次重试时间单独存储，失败也留日志。每天是否已签以面板配置时区的当天成功日期判断。
- `retries` 表示额外重试次数（0–5）；默认每轮最多 3 次尝试。失败退避为 60、120、240…秒，上限 3600 秒，Telegram FloodWait 优先遵守服务器要求。
- 签到严格使用同日半开窗口 `[开始,结束)`，窗口结束不再开始/重试，并取消超窗的后续步骤。
- 保号新任务仍先等待一个配置间隔；失败采用有次数上限的短退避，不会因为一次失败马上等待整个七天间隔。失败耗尽后才回到完整间隔，避免无限刷消息。
- 手动执行和定时执行共用任务锁，防止重复并发；监听开关仍只控制群消息监听，不改成全局任务暂停。
- 升级保留旧 `last_at`，因为旧版历史记录无法可靠区分成功和失败，不会为了修复而擅自重签全部任务。

## 备份空间清理

设置 → 系统更新 → 查看备份，显示数量、文件逻辑大小及时间；可保留最新一份可回滚代码备份并清理其余，或确认后删除全部备份。

删除后不能回滚到这些备份版本。只识别 `data/backup-YYYYmmdd-HHMMSS` 与 `data/update-<uuid>` 更新目录；数据库、账号会话、运行配置和虚拟环境不会删除。更新、恢复进行中或目录不安全时，服务器拒绝清理；删除与更新共用文件锁。

空间显示为文件逻辑大小，不等同于真实磁盘分配块。删除途中若权限/I/O 出错会停止，可能已有部分备份删除，需重新查看列表。功能不会自动清理，也不会替用户判断新版本是否稳定。

## 1.3.0：账号级任务队列与异常处理中心

- **任务队列**：每账号独立排队，默认并发 2（可设 1–5）。按面板任务顺序 `id DESC` 分批；必须等当前整批全部结束，才启动下一批。设置变化从下一批生效，不中断当前任务。
- **协调重试**：初始轮全部任务结束后，仍有额度的失败任务才按原顺序进入下一轮；该轮按最晚退避时间统一开始。成功、待确认、停用、手动停止和额度耗尽不会再次排队。
- **手动停止**：任务卡片可停止运行任务或取消排队，批量区可停止当前账号全部任务。停止会取消等待、点击和识别，记录“用户手动停止”，不计普通失败、不触发 Bark、不自动重试；其他账号不受影响。
- **异常中心**：日志页“回复”后新增异常分类，集中显示失败、待确认、中断和已停止任务。可以人工确认成功、标记失败、再执行一次或停用；所有动作仅作用当前账号并需确认。
- **密钥只写不读**：`/api/settings` 不再返回完整 AI Key，只返回是否已保存；输入框始终为空，留空保存沿用旧值，填写新值才替换。切换账号、浏览器缓存和页面变量均不保存密钥。
- **移动端轮询**：页面退到后台后暂停 5 秒状态/日志刷新，回到前台立即刷新当前页，减少小 VPS 和手机耗电。

队列及异常状态存于各账号数据库；现有任务、执行记录、账号会话和重试额度不会因为升级被清空。

## 1.2.1：AI兼容与签到结果确认修复

- GLM-5.3/5.3-Flash 文本助手按官方要求保持思考开启并改用低思考强度、8192输出预算；图片验证码识别请求保持原样。空正文、仅思考和输出截断会显示不同原因，不把内部推理当作任务JSON。
- 签到新增“结果判断前延迟”(默认0秒)和“等待最终回复上限”(默认30秒，最大300秒)，在上限内持续轮询新回复及同消息编辑。
- “恭喜获得 + 当前持有 + 当天签到日期”视为明确成功，即使自定义成功词写成“成功”也不会误报失败；多条回复按最新消息优先。
- 结果仍未知时记为黄色“待确认”，当天停止自动重发；按钮回调消息ID失效时先等待机器人最终结果，不能只因点击异常直接判失败。
- 自动失败的中间重试只记日志，不推Bark；耗尽后持久去重只推一次。修改重试设置不重置当天已经消耗的额度，设为0后不会继续沿用旧重试计划。

## 1.2.0：AI 助手闭环

- **说人话建任务**：自动化页新增默认折叠的 AI 助手。描述目标、命令、时间和步骤后只生成配置预览；可填入现有可视化表单继续修改，或二次确认保存为停用任务。AI 不能自动保存、启用或执行，也不能自动开启验证码识别。
- **AI 任务排障**：展开签到、自定义或保号任务后点「AI 排障」，只读取当前账号、当前任务最近的脱敏日志。验证码答案、密钥、长凭据、手机号和图片均不会发给 AI。分析只给建议；每条参数建议必须单独确认，并在应用前重新读取任务，配置已变化时拒绝覆盖。
- 草稿只支持签到、自定义步骤和保号任务；可视化步骤仅发送、等待、点击和等待回复。额外验证由用户人工处理后等待确认，不生成自动破解步骤。
- AI 请求使用设置中已保存或当前填写的 OpenAI 兼容配置，可能产生服务商费用。生成结果和排障建议可能出错，保存/应用前必须人工复核。

## 1.1.0：多账号和可视化任务管理

- **账号**：顶部选择当前账号，设置中新增、改名和删除。旧账号/任务自动作为默认账号保留；其它账号在 `data/accounts/<id>/` 使用独立数据库、会话和头像。不同账号可同时登录，任务、监听群、规则、日志、冷却、暂停和重试状态互不混用。面板密码、AI/通知、时区、图标库和统一时间仍共用。默认账号不可删除，最多20个账号；小内存VPS建议先使用2–3个。
- **步骤编辑器**：自定义任务用发送、等待、点击、等待回复卡片配置；支持排序、删除和示例模板，界面单位为秒。高级JSON默认折叠，旧步骤保留；涉及额外验证可用人工处理后等待确认，不新增自动破解入口。
- **批量管理**：任务多选后修改签到窗口、保号/轮询间隔，或启停、删除；先预览适用任务与跳过原因，再确认保存。只修改当前账号，执行中的任务禁止修改。
- **导入/导出**：下载当前账号全部或选中配置；导入2MB以内备份文件，先预览，再选择追加或覆盖当前账号。默认新任务/规则禁用，明确勾选才恢复启用状态。备份不含系统密钥、登录会话或历史执行状态，但任务文本可能包含自行填写的敏感信息，请勿公开分享。
- **任务卡片**：默认收起，只显示图标、名称、状态和操作；展开查看有效窗口、配置、账号归属及上次结果。同账号刷新保留展开状态，切换账号清空。
- **图标库**：默认内置 TFEL `https://emby-icon.vercel.app/TFEL-Emby.json`，设置中添加/启停/删除外库，任务编辑时选择图标。支持名称映射与 icons 数组；缓存JSON、不缓存图片，所有设备与账号共用。图标库只允许公网HTTP(S)来源，最多10库、每库2000图标。
- **统一签到时间**：在签到列表顶部开启，默认窗口00:05–00:41；所有账号的签到在统一窗口内随机开始。任务原窗口保留但暂不生效；关闭后恢复单任务窗口。已执行成功的任务不重新签到，已在执行的任务不强行中断；保号与轮询间隔不受影响。

本版本没有引入大型依赖。旧单账号数据不移动，新增账号数据不参与代码备份清理；程序升级仍走 main。
